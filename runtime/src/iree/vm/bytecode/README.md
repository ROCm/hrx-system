# IREE VM Bytecode Specification

The declarative Python model in [`spec/model/`](spec/model/) is the sole
editable authority for the VM module format and instruction set. Revisioned
facts follow the format hierarchy: `model/module/v0/` defines the container,
`model/isa/core/` defines the required ISA, and `model/isa/hal/` defines the
optional HAL page. ISA sources contain all revisions together and each entity's
`since` field controls version projections; revisions never require copied or
overlaid source trees. Rendering and generation tooling live beside the model
under `spec/`, not inside it.

The complete human specification is generated only while building the Loom
documentation site and is published as the
[VM bytecode reference](https://rocm.github.io/hrx-system/loom/reference/vm/).
Its ISA hierarchy follows architectural ownership: `isa/core/` contains the
required machine and instructions, while `isa/hal/` contains the optional HAL
extension page. Generated Markdown is not checked in.

[`wire/`](wire/) contains the checked-in natural-layout C projection used by
runtime-only and compiler builds that do not execute Python. Its public headers
contain declarations only; private generated C translation units compile the
layout assertions once as part of the package library.

Regenerate the checked-in wire projection from the repository root with:

```shell
iree-bazel-run //runtime/src/iree/vm/bytecode/spec:generate
```

The generator owns a closed set of wire paths and refuses to overwrite
unexpected files. Presubmit uses the corresponding freshness test to reject
missing, stale, or unexpected files. `python dev.py docs build` independently
projects the Markdown into the documentation build tree.

There is intentionally no standalone test-only bytecode reader or writer. A
third handwritten codec and a checked-in corpus generated by it would test
agreement with another authority, not production interoperability. The first
cross-implementation conformance suite belongs to the Loom writer/runtime
loader vertical slice: model-level source cases are serialized by Loom, loaded
and inspected through runtime APIs, and mutated to exercise production
verification failures. Compact authored cases are durable inputs; generated
binary and JSON change detectors are not.

This directory currently specifies the bytecode contract. It does not claim a
shipping loader, verifier, interpreter, or Loom target; those consumers land as
separate implementation units after this authority is accepted.
